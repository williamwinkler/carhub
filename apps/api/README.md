# Carhub API

NestJS API for Carhub. The app exposes two intentional API surfaces:

- **tRPC for first-party TypeScript consumers:** JWT bearer auth, type contract exported through `@repo/api-contract`.
- **REST/OpenAPI for non-TypeScript or external programmatic consumers:** `x-api-key` auth, Swagger/OpenAPI available at `/docs` and `/swagger.yml`.

Do not mix the auth models by default. tRPC should not accept API keys, and protected REST controllers should not accept JWT bearer tokens.

## tRPC architecture

The tRPC implementation uses `nestjs-trpc` so routers, context, middleware, and DI are Nest-native providers/decorators instead of a raw Express policy island.

Key files:

- `src/modules/trpc/trpc.modules.ts` wires `TRPCModule.forRoot(...)`.
- `src/modules/trpc/trpc.context.ts` builds the JWT-only tRPC request context.
- `src/modules/trpc/trpc.middlewares.ts` owns request context, AppError mapping, JWT auth/admin checks, and rate limiting.
- `src/modules/**/*.trpc.ts` contain thin procedure classes.
- `src/@generated/server.ts` is generated by `nestjs-trpc` and exports the runtime `AppRouter` type shape.
- `src/modules/trpc/trpc.router.ts` is the compatibility type export consumed by `@repo/api-contract`.
- `src/modules/trpc/README.md` documents the copy-this pattern for new namespaces.

Regenerate and check the tRPC router type after changing decorators or
procedure inputs/outputs:

```bash
pnpm --filter api trpc:generate
pnpm --filter api trpc:check
```

## Tests

The API uses separate Jest projects:

```bash
pnpm --filter api test:unit
pnpm --filter api test:integration
pnpm --filter api test:e2e
pnpm --filter api test
```

Test layer intent:

- Unit specs cover isolated service/guard behavior, including API-key-only REST auth.
- tRPC integration specs call the real `nestjs-trpc` router with mocked service boundaries.
- HTTP e2e specs start a Nest test app and use `@trpc/client` for `/trpc` wire behavior.

## Local development

```bash
pnpm install
cp apps/api/.env.example apps/api/.env.local
docker compose up -d
pnpm --filter api migrations:run
pnpm --filter api dev
```

Swagger UI is available at `http://localhost:3001/docs` in development.
